# ShipShield — Ubuntu Launchpad PPA Release Runbook

## 1. Overview & Security Protocols

This runbook details the exact manual steps required for the maintainer to cryptographically sign, inspect, and upload the **ShipShield** Debian source package to an **Ubuntu Launchpad Personal Package Archive (PPA)**.

### Strict Release Boundaries:
- **Source Upload Only**: Launchpad strictly builds binary `.deb` packages inside isolated, networkless chroots. **Never** attempt to upload the pre-built `.deb` binary package to a PPA.
- **Maintainer Signing**: GPG cryptographic signing must take place on your secure local workstation using your Launchpad-registered private key.
- **No Automated Credentials**: This pipeline generates unsigned, verified source packages and leaves private key signing and `dput` upload entirely under your manual command.

## 3. GPG Key Verification & Launchpad Registration

Launchpad requires that all uploaded `.changes` and `.dsc` files be signed by a GPG key registered and verified on your Launchpad account.

### Step 3.1: Locate Your Local GPG Secret Key ID
List your secret keys:
```bash
gpg --list-secret-keys --keyid-format long
```

Sample output:
```
sec   rsa4096/8A7B6C5D4E3F2A10 2026-01-01 [SC]
      E2B04B5C6D7E8F9A0B1C2D3E4F5A6B7C8D9E0F1A
uid                 [ultimate] Kashif Memon <Kashifjaanmemon786110@gmail.com>
ssb   rsa4096/1A2B3C4D5E6F7A8B 2026-01-01 [E]
```
In this example, your GPG Key ID is `8A7B6C5D4E3F2A10` (or the full fingerprint).

### Step 3.2: Export Public Key to Keyserver (If not already registered)
```bash
gpg --keyserver keyserver.ubuntu.com --send-keys 8A7B6C5D4E3F2A10
```

### Step 3.3: Register Key on Launchpad
1. Navigate to: [https://launchpad.net/~/+editpgpkeys](https://launchpad.net/~/+editpgpkeys)
2. Paste your GPG fingerprint and click **Import Key**.
3. Launchpad will send an encrypted email to your address. Decrypt the message using `gpg --decrypt` and follow the confirmation link.

## 5. Step-by-Step Signing & Upload Workflow

### Step 5.1: Build Release Artifacts (If not already built)
From the repository root:
```bash
./packaging/build-deb.sh
```

### Step 5.2: Cryptographically Sign the Source Package
Use `debsign` to sign both the `.dsc` and `_source.changes` files using your GPG key:

```bash
debsign -k <YOUR_GPG_KEY_ID> dist-deb/shipshield_1.0.0-1~ubuntu24.04.1_source.changes
```

Verify that the signature was applied:
```bash
dscverify dist-deb/shipshield_1.0.0-1~ubuntu24.04.1_source.changes
```

### Step 5.3: Configure `dput` (Optional ~/.dput.cf)
If you haven't already configured `dput`, ensure `~/.dput.cf` has standard Launchpad settings (by default, `dput ppa:...` uses Launchpad FTP without requiring custom config):

```ini
[DEFAULT]
default_host_main = ppa

[ppa]
fqdn = ppa.launchpad.net
method = ftp
incoming = ~%(ppa)s/ubuntu
login = anonymous
```

### Step 5.4: Upload to Launchpad PPA
Upload the signed `.changes` file to your Launchpad PPA:

```bash
dput ppa:<YOUR_LAUNCHPAD_USERNAME>/<YOUR_PPA_NAME> dist-deb/shipshield_1.0.0-1~ubuntu24.04.1_source.changes
```

*Example for user `kashifhm333` and PPA `shipshield`:*
```bash
dput ppa:kashifhm333/shipshield dist-deb/shipshield_1.0.0-1~ubuntu24.04.1_source.changes
```

## 6. Monitoring & Build Acceptance

1. **Email Confirmation**: Launchpad will send an email with subject:
   `[PPA <username>/<ppa>] shipshield 1.0.0-1~ubuntu24.04.1_source.changes ACCEPTED`
   *(Usually within 1–5 minutes).*
2. **Build Queue**: Visit your PPA web page:
   `https://launchpad.net/~<YOUR_LAUNCHPAD_USERNAME>/+archive/ubuntu/<YOUR_PPA_NAME>`
3. Monitor the build logs under the **Builds** tab. Launchpad will allocate a clean Ubuntu 24.04 (*noble*) builder, extract `shipshield_1.0.0.orig.tar.gz`, apply `debian.tar.xz`, execute `debian/rules binary`, and package the binary `.deb`.
4. Once marked **Published**, the package is immediately installable by users.

## 7. Subsequent Uploads & Version Incrementing Rule

> **CRITICAL LAUNCHPAD CONSTRAINT**:
> Launchpad PPA strictly rejects any source upload with a version number that has previously been accepted by the archive.

If an upload is rejected or if you are publishing a subsequent update/patch:
1. Increment the Debian package revision in `debian/changelog`:
   - First release: `1.0.0-1~ubuntu24.04.1`
   - Second iteration / fix: `1.0.0-1~ubuntu24.04.2`
   - New upstream version: `1.0.1-1~ubuntu24.04.1`
2. Update `debian/changelog`:
   ```bash
   dch -v 1.0.0-1~ubuntu24.04.2 -D noble "Packaging fix or revision notes."
   ```
3. Re-run `./packaging/build-deb.sh` to generate the new release candidate.
4. Sign with `debsign` and re-upload with `dput`.
